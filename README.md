# Restaurant Lab · 餐厅实验室

浏览器本地运行的 2D 俯视餐厅经营模拟 MVP。玩家安排布局、员工和菜单，厨师与服务员自行走路和执行任务。订单经过食材领取、实际加工、装盘、出餐、送餐、用餐、结账和清洁；收入在结账时产生。

React + TypeScript + Vite 提供界面，Phaser 3 绘制游戏，独立 TypeScript 引擎负责全部经营逻辑。无需后端、账号或外部服务。视觉素材由程序绘制。

## 安装与运行

推荐 Node.js **24.19** 与 npm **11.9**；最低 Node.js 22.12。项目记录了 Node 版本与 npm 版本，依赖锁定在 `package-lock.json`。

```bash
npm ci
npm run dev
```

打开终端显示的地址，默认 `http://localhost:5173`。开发服务器监听 `0.0.0.0`，可以使用云端端口预览。

```bash
npm test              # Vitest 自动化测试
npm run simulate      # 无画面的两种布局完整午餐实验
npm run build         # TypeScript 检查及生产构建
npm run preview       # 预览 dist/，默认端口 4173
```

`dist/` 可以部署到静态网页服务器。所有模拟和存储都在本地浏览器进行。

## 游戏操作

1. 打开页面，默认已有 30×20 餐厅、八件厨房设备、三张四人桌、两名厨师、一名服务员，以及三道菜。
2. 营业前可选择布局、随机种子、到店间隔、员工数量和菜单。
3. 点击 **开门营业 / Start Business Day**，观察顾客入店、服务员点单、厨师加工、上菜和结账。下方支持暂停和 1×、5×、20×、60×。
4. 点击人物、设备、桌子查看真实任务、状态、等待或进度。调试视图提供员工路线与设备占用。鼠标滚轮缩放，右键拖动画布移动视野。
5. 点击 **编辑餐厅布局**，从左侧选择设备并在格子上放置；选中设备后可移动、旋转和删除。非法重叠、挡住入口、无操作位置或不可达的布局会被拒绝。
6. 营业中的布局编辑会重置本次营业，然后暂停编辑，防止正在加工时移动设备损坏状态。可以保存、载入或恢复布局；保存的是布局，当前营业进度不保存。
7. 在 **分析** 面板点击 **比较两种布局**。程序实际运行相同种子、同一份预生成需求、同样设备与人员的两个午餐实验，显示模拟统计，无预置效率加成。
8. 14:00 停止新需求；已经接待的顾客继续用餐，员工完成清洁后显示报告，因此结束时间可能晚于 14:00。

菜品包括香煎鸡肉饭、鸡排咖喱饭和蔬菜炒饭。厨师会逐站领取中间食材并搬至下一工位；米饭以六份批次共享；炸炉油炸期间会释放厨师，设备仍占用；煎炒要求持续劳动。

## 模拟范围与限制

所有食材价格、工资、到店分布、加工时间、用餐时长和顾客耐心都是游戏初始假设，**不是经过验证的餐饮统计数据**。货币是游戏记账单位。

- 顾客组大小目前为一人或两人，餐桌支持四个座位。
- 每种初始食材 400 份；尚无采购、员工成长、复杂食品安全、工具损坏或设备维护。
- 非米饭食材统一在冰箱领取；生米在储物架领取，尚未模拟每种原料独立储存位置。
- 工具以设备可用工具清单验证，不模拟独立移动工具库存。
- 出餐台容量限制并行取放任务，尚不限制等待配送的餐盘存放总量。
- 有基础卫生间离座行为，会预约单人容量、真实行走并保留席位；卫生间采用外部交互位置与停留时间，尚无独立房间内部移动。
- 布局建造不扣除资金；设备购买价为扩展数据，目前利润仅计算实际食材、人工和运营成本。
- 存档仅包含布局，不能恢复营业中的订单与任务。
- 有基础拥堵协调与重寻路；极端自定义窄通道仍可能长时间阻塞。缺少必要设备时依赖订单不能完成，会显示等待或超时诊断。
- 没有后端、联机、手动接管、热力图或复杂卫生系统。

运行规则见 [SIMULATION_RULES.md](SIMULATION_RULES.md)，代码模块见 [ARCHITECTURE.md](ARCHITECTURE.md)，后续开发见 [ROADMAP.md](ROADMAP.md)。

## 验证

测试覆盖寻路与静态碰撞、动态占位、设备容量与工位锁、加工状态与工具、任务依赖和唯一分配、食材扣除、顾客结账离店、财务记账、确定性、暂停与速度一致性、布局实验以及完整 11:00–14:00 无渲染营业。

可选的 Chromium 浏览器检查与 Vitest 分开执行。先保持开发服务器运行，再在另一个终端执行：

```bash
node scripts/browser-smoke.mjs
```

该脚本使用 `http://127.0.0.1:5173` 和 `/usr/bin/chromium`；可设置 `RESTAURANT_LAB_URL` 与 `CHROMIUM_PATH` 指定地址和已安装的 Chromium 路径。它需要开发服务器，因为会读取仅在开发模式提供的模拟检查入口。检查实际界面操作、营业循环、暂停/倍速、布局编辑和存档、实验结果，并在 `artifacts/` 写截图及观察记录；首次真实渲染营业之后，剩余午餐通过固定模拟步快速完成。它不属于 `npm test`。

命令行 `npm run simulate` 默认到店间隔 150 秒，网页初始标准档位 210 秒；网页实验使用当前设置，比较结果时应先统一输入条件。

运行结果以实际终端输出为准；测试失败时不要把营业日标记为成功。`npm run simulate` 输出真实经营指标和设备使用率，并在营业无法正常结束时返回错误。
